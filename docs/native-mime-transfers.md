# Native MIME transfers on Linux

`ClipboardItem::new_mime` and `ExternalDragPayload::Mime` carry immutable `MimeRepresentation` values. Each representation has its own exact type and `Arc<[u8]>` bytes. Cloning the payload shares those bytes. Type names supplied by an application are opaque to GPUI. `MimePayload::offered_types` exposes bounded native offered names, including unfetched standard alternatives. `with_offered_types` records at most 64 distinct names of at most 4096 bytes each. X11 resolves TARGETS names asynchronously and requests the preferred standard representation plus offered opaque MIME representations. They share one aggregate byte ceiling and one absolute deadline.

Text and image constructors remain available. An `ExternalPaths` clipboard entry advertises escaped local file URLs through `text/uri-list`, GNOME's `copy` file representation, and plain-text aliases. To publish Cut intent, supply both the URI and GNOME representations with `SelectionIntent::Cut`:

```rust
use gpui::{ClipboardItem, MimePayload, MimeRepresentation, SelectionIntent};

let item = ClipboardItem::new_mime(MimePayload::new([
    MimeRepresentation::new("text/uri-list", &b"file:///example/a%20b\r\n"[..]),
    MimeRepresentation::new("x-special/gnome-copied-files", &b"cut\nfile:///example/a%20b\n"[..]),
], SelectionIntent::Cut));
```

`SelectionIntent` describes the application snapshot. It does not rewrite arbitrary representation bytes. The application must supply consistent GNOME bytes and intent. GPUI does not copy, move, delete, inspect or stat the selected files. Selection validation, collision handling, operation tokens and source removal remain application responsibilities.

Use `App::read_from_clipboard_async` or `App::read_from_primary_async` for a foreign selection. The synchronous API returns an owned item or a completed cache; it starts acquisition when uncached and returns `None` while acquisition is pending. Wayland starts a background read when a selection arrives. X11 starts acquisition for existing CLIPBOARD and PRIMARY owners during initialization, on XFixes ownership events, and on uncached reads, using its existing connection. Async Wayland reads join a pending prefetch, including a paste requested before the prefetch completes. A foreign file selection prefers GNOME data for Cut intent, then a URI list with Copy intent. Text and image entries retain their normal decoded entry types alongside the selected MIME representation.

`App::on_clipboard_change` reports ownership changes, clear events and receive errors with a generation. Discard work associated with an earlier generation. `clear_clipboard_if_owned` refuses to clear a foreign selection. Applications that already have an external clipboard helper must bridge the helper's validated snapshot to this owner instead of having both claim the native selection.

For native drags, supply `NativeDragPayload` with representations, a source identity, allowed actions and a preference. Ctrl selects Copy when permitted, Shift selects Move when permitted, and otherwise the preference chooses the action at lift. Wayland advertises that chosen action. The legacy `Files` payload retains its Copy and Move mask. Wayland has no Link action bit; an application's semantic link marker belongs in its own MIME bytes and is handled by its backend.

`App::on_native_drag_offer` chooses destination actions at Enter, before receiving data or processing Drop. Its default permits only Copy. An application can permit and prefer Move for its own validated operation policy; ordinary foreign drops can keep the Copy default. Offered type names alone do not validate an application token.

`App::on_native_drop` exposes advertised types, successfully selected representations, latest position, modifiers and the selected transport action. It is called on entry and again with `dropped: true` when submitting. The callback receives the payload before deciding whether to accept it. Return false to reject the destination; a refusal sends no legacy Submit event. A refused destination, by this callback or by a failed read, withdraws its acceptance with the Enter serial and stops its read. The refused offer stays alive until Drop settles it or the next Enter releases it. Existing `ExternalPaths` drop handlers still receive legacy file events, so applications should arrange one transfer authority. An opaque token never becomes an `ExternalPaths` entry. Without a MIME handler, a plain-text-only drag is rejected. GPUI never reads an X selection request type that GTK lists among a drag's targets, such as `DELETE`, which asks the source to delete its data and is never answered with an end of file.

On Hyprland the MIME type remains unaccepted throughout hover, including after a successful read and an allowed entry callback. Only the final allowed submission accepts the selected type and immediately sends finish. A refused drop finishes with no type accepted, so Hyprland cancels its current source. Other compositors accept at Enter and destroy an offer refused after Drop. In [Hyprland v0.53.0 `src/protocols/core/DataDevice.cpp`, lines 44 to 65](https://github.com/hyprwm/Hyprland/blob/ea444c35bb23b6e34505ab6753e069de7801cc25/src/protocols/core/DataDevice.cpp#L44-L65), receive already reports the type to the source and records `m_recvd`; `wasDragSuccessful` accepts that flag at lines 760 to 769. The finish handler at lines 71 to 77 calls `abortDrag` without an accepted type, otherwise `completeDrag`. GPUI recognizes Hyprland's own data device, introduced in v0.41, by the exact global `hyprland_surface_manager_v1`, first shipped after v0.41. Earlier wlroots versions use the ordinary destroy path. Hyprland sends source actions and an action before Enter and never answers `set_actions`, so GPUI chooses the destination's preferred transport action when the source permits it, otherwise its other permitted action. When neither action is permitted, GPUI refuses the offer at Enter like any refused offer: no type is read, nothing reaches the drop callback, and the drop ends as a cancel.

Hyprland can stop tracking an offer after Drop while retaining its source. [`dropDrag`, lines 727 to 756](https://github.com/hyprwm/Hyprland/blob/ea444c35bb23b6e34505ab6753e069de7801cc25/src/protocols/core/DataDevice.cpp#L727-L756), retains `currentSource` via `cleanupDndState(false, false, false)`, and `dndActive` at lines 842 to 844 tests that source. [`SeatManager.cpp`, lines 213 to 223](https://github.com/hyprwm/Hyprland/blob/ea444c35bb23b6e34505ab6753e069de7801cc25/src/managers/SeatManager.cpp#L213-L223), can therefore emit a drag pointer focus change after Drop when the pointer reaches a different surface. The listener calls `onDndPointerFocus` (`DataDevice.cpp`, line 397), which marks prior drag offers dead at lines 547 to 554. A late accept is ignored for a dead offer (lines 33 to 36). Consequently a successful late read may reach the application while its finish reports cancellation to the source; no client request revives that offer.

A newer drag also makes finish unsafe for an old pending drop: the finish handler acts on the compositor's current drag, regardless of the offer's source. `initiateDrag` at [`DataDevice.cpp`, lines 557 to 563](https://github.com/hyprwm/Hyprland/blob/ea444c35bb23b6e34505ab6753e069de7801cc25/src/protocols/core/DataDevice.cpp#L557-L563), first aborts the old drag; `abortDrag` cancels its source at lines 810 to 811, and pointer focus changes mark its offers dead. Once this client observes another Enter or starts a native drag, GPUI cancels the old pending read and destroys its dropped offer without finish. The destructor at lines 80 to 85 sends nothing for a dead offer; destroying a live drag offer instead sends `dnd_finished`, so destroy alone is not a general cancellation mechanism. A newer drag in another client that never enters this client remains a compositor limitation: the old read can still finish against that newer drag before its two-second transfer deadline. Source inspection and headless offer tests do not establish native interoperability.

`App::on_native_drag` reports selected action, pointer release, native finish and cancellation for the supplied source identity. Hyprland never sends a source an action, so when the compositor names none, Dropped and Finished report the lift's action if it offered only one, and none if it offered both. A finish is transport completion and never authorizes GPUI to remove source files. Starting a native Wayland drag requires the held left-button grab on the source surface. Pending incoming reads survive Drop and its following Leave, while a genuine Leave or a new destination cancels the previous generation.

Native pipe transfers have an absolute two-second deadline and a 64 MiB receive ceiling, with at most 100,000 decoded local paths. Known aliases are represented by the preferred MIME rather than fetched repeatedly. Additional opaque types share the receive ceiling. Sends are capped at 64 MiB per representation and run nonblocking. At most sixteen Wayland transfers are admitted concurrently. X11 bounds incoming and outgoing INCR state to sixteen sessions per direction, reads properties in 64 KiB slices and expires active transfers after two seconds. Its transfer timer is absent while idle; ownership uses XFixes events and never polling or a helper process. Before quit or a requested display-mode change, it offers SAVE_TARGETS to an existing clipboard manager on the same connection and waits asynchronously for acknowledgement or the bounded deadline.

Headless tests use in-process Wayland offer and X11 selection fakes, real anonymous pipes, and the same lifecycle helpers called by the platforms. These are deterministic protocol and transport tests. They do not establish compositor, clipboard-manager or file-manager interoperability, native frame time, or process memory cost.
